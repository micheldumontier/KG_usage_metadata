# `generated-usage-metadata/` — index

The paper's actual usage-metadata deliverable and the schema/content data it's measured
against. Downstream analyses that *consume* this data to produce a specific table or figure
live in `analysis-results/`, not here. Superseded/unused material lives in `archive/`.

## Central files (root-level `*_combined_schema_elements.csv` + `.ttl`)

One row per referenced schema element (`Schema Element,TotalCount`), one file per
log/KG-version pair (e.g. `Bio2RDF organic log2019KG2024_combined_schema_elements.csv`). The
matching `.ttl` files are an RDF serialization of the same counts (produced by `csv-2-rdf.ipynb`).

## Schema totals (Table 3)

- `bio2rdf-schema/`, `bio2rdf-schema-release{2,3}/` — Bio2RDF schema, current + historical
- `wikidata-schema/` — Wikidata schema (2017/2018)
- `schema-Bio2RDF-17Subgraphs.csv` — Bio2RDF schema restricted to 2013-log-covered subgraphs

## Other

- `wikidata-supply/` — KG-content baselines (instances/class, triples/predicate)
- `wdqs-examples/` — WDQS example-query set (not generated by this pipeline; a small
  committed input dataset)

## About `out/`

Most `KG-Usage-analysis/` scripts write their raw run output to `out/` by default (gitignored,
never committed) — that's a scratch directory, not a results store. When an output is small and
worth keeping for traceability, it's copied into the matching folder here or in
`analysis-results/`; each folder's README says which files are the permanent copies. Files still
sitting in `out/` after a run are disposable — rerun the script to regenerate them.
